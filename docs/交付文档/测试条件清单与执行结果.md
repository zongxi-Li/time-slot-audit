## 3. 接口级实测记录（curl）

环境：临时后端实例（8082 端口）+ 本地 MySQL 真实种子数据；admin 登录取 token。实测完成后实例已停止，未影响 8081 正式实例。

### 3.1 场景与响应

| 场景 | 请求 | 响应摘要 |
| --- | --- | --- |
| 1. 设施+容量筛选 | `GET /api/rooms?facility=投影&minCapacity=10` | `SUCCESS`，返回 B201、B202、B502（均含投影、容量≥10） |
| 2. 位置模糊筛选 | `GET /api/rooms?location=教学楼B` | `SUCCESS`，返回 B201、B202、B502 |
| 3. 空闲查询（占用剔除） | `GET /api/rooms/available?date=2026-09-24&startTime=13:00&endTime=16:00` | `SUCCESS`，10 间；D301（当日 13:00–15:00 已有 CONFIRMED 预约）被正确剔除 |
| 4. 空闲查询（跨天推导） | `GET /api/rooms/available?date=2026-09-21&startTime=22:00&endTime=02:00` | `SUCCESS`，按 22:00–次日 02:00 判定，11 间空闲 |
| 5. 参数缺失 | `GET /api/rooms/available?startTime=13:00&endTime=16:00` | HTTP 400，`VALIDATION_ERROR`「缺少必需参数：date」 |
| 6. 参数格式错 | `GET /api/rooms/available?date=abc&startTime=13:00&endTime=16:00` | HTTP 400，`VALIDATION_ERROR`「参数格式无效：date」 |
| 7. 非法容量 | `GET /api/rooms?minCapacity=0` | 400，`VALIDATION_ERROR`「最小容量必须为正整数」 |

### 3.2 与数据库口径交叉核对

筛选与占用 SQL 先在 MySQL 中直接执行核对，再经接口验证：设施含「投影」且容量≥10 命中 B201/B202/B502；2026-09-24 13:00–16:00 的占用查询仅命中会议室 9（D301），与 `reservation` 表中的 CONFIRMED 预约（13:00–15:00）吻合，同日 09:00–11:00 的预约与该时段不重叠、未误判。
