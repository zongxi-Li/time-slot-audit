## Git 提交规范

统一使用 Conventional Commits：

```text
<type>(<scope>): <简短说明>
```

允许的 `type`：`feat`、`fix`、`refactor`、`test`、`docs`、`chore`、`ci`。

`scope` 必须使用当前负责 Domain，例如：`administration`、`identity`、`meeting`、`resource`、`reservation`。公共工程任务可使用 `ci`、`build`、`docs`。

禁止以下提交信息：`update`、`修改`、`完成任务`、`最终版`、`111`。

推荐：

```text
feat(resource): 实现会议室与分类管理
fix(reservation): 限制取消操作仅允许预约本人
refactor(meeting): 收敛签到状态转换逻辑
test(identity): 补充禁用账号与越权场景测试
docs(administration): 补充审批模块接口说明
```

每个 commit 应保持**单一职责、可独立解释、可回滚**。不要把数据库、后端、前端、测试全部堆成一个超大 commit。

## 并行开发约束

1. 不直接访问或修改其他 Domain 的 Mapper / 数据表；跨域写操作必须调用对方公开 Service。
2. 不修改历史 migration；每个成员只新增自己被分配的 migration 文件。
3. 为降低五人并行冲突，本轮 feature 分支**不要直接重写 `sql/schema.sql`**；只新增 migration。最终由组长在集成阶段统一同步完整快照。
4. 不擅自修改冻结的 `core-business-contract.md`。如发现必须改变核心语义，新增 `docs/development/proposals/<domain>-contract-change.md` 并停止相关实现，交由组长评审。
5. 新前端业务代码优先放入 `frontend/src/modules/<domain>/`；避免继续把新业务堆进全局 `stores/`、`views/`、`shared/api/index.ts`。
6. 对 `router/index.ts`、`MainLayout.vue`、全局菜单等共享文件的改动必须小而独立，单独 commit，方便组长处理冲突。
7. 不改别人负责的 UI 页面，不顺手实现其他 Domain 的需求。
8. 不引入 Redis、MQ、微服务、工作流引擎或复杂 RBAC，除非本任务明确要求。
9. API 统一返回 `ApiResponse<T>`；错误码遵守现有全局约定。
10. 预约时间语义继续遵守 `[start,end)`，`PENDING/CONFIRMED` 占用时间，`REJECTED/CANCELLED` 不占用。

## P0：必须完成

### 1. 参与人管理

接口建议：

```text
GET    /api/meetings/{reservationId}/attendees
POST   /api/meetings/{reservationId}/attendees
DELETE /api/meetings/{reservationId}/attendees/{userId}
```

规则：预约创建人或有权限用户才能管理；参与人不重复；CANCELLED/REJECTED 不允许新增；人数约束通过公开 Query Service 获取，不直接读别域 Mapper。

### 2. 签到/签退

```text
POST /api/meetings/{reservationId}/check-in
POST /api/meetings/{reservationId}/check-out
GET  /api/meetings/{reservationId}/attendance
```

只有参与人可签到；签到窗口与预约时间相关；记录服务器时间；未签到不能签退；重复操作必须幂等或给出明确业务错误。

### 3. No-Show 判定

预约结束后，没有签到的参与人进入 `NO_SHOW`。逻辑必须可测试、可重复执行、不会重复副作用。不要用无限循环线程硬跑。

如需影响 identity 信用，只调用 identity 对外 Service；接口未就绪时记录集成点，禁止直接写 identity 表。

### 4. 用户前端闭环

新代码放：`frontend/src/modules/meeting/`。

完成：课表式日历与预约详情整合、我的预约、参与人管理、签到/签退、No-Show 状态、历史记录、个人通知入口。必须使用真实后端 API。

## P1：建议完成

业务内通知：被加入会议、预约即将开始、预约取消/审批结果。支持通知列表与已读状态。
